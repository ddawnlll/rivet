# BUG-007 — Store CAS / STALE_STATE rejection

**Status:** IMPLEMENTED / FULL-GATE VERIFIED; REVIEW PROTOCOL-LIMITED  
**Priority:** P2

## Symptom and evidence

[OBSERVATION] `HardStateStore::append_event` previously accepted only an event and let each backend derive the current revision, so concurrent writers had no semantic expected-revision contract.

[INFERENCE] Transaction serialization alone did not express that a writer had validated a specific base revision.

## Root cause and discriminating observation

[OBSERVATION] Two concurrent `MemoryStore` appends at `Revision::ZERO` now produce exactly one `Revision(1)` and one typed `RivetError::StaleState { expected: Revision::ZERO, actual: Revision(1) }`. Receipt: [.rivet/audit/evidence/BUG-007-store.txt](/C:/Users/dresden/Documents/rivet/.rivet/audit/evidence/BUG-007-store.txt).

## Final diff summary

[OBSERVATION] The store trait and both backends now take `expected_revision`, compare it while holding the backend write lock/transaction, and reject mismatches with `STALE_STATE`. Harness event recording passes its observed revision and checks the returned next revision. The event schema was unchanged.
