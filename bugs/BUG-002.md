# BUG-002 — Model-generated verification is likely rejected at the post-invocation revision

**Status:** OPEN / NEEDS REPRODUCTION  
**Priority:** P1  
**Scope manifest:** `crates/rivet-core/src/lib.rs` and a new focused test only, after the tree is stable.

## Symptom and evidence

[OBSERVATION] The model receives a view at `view_revision` (`crates/rivet-core/src/lib.rs:274-280`). The Harness then records `ModelInvocationRecorded` (`:288-303`), which advances Hard State by one revision. For a `VerificationRequest`, the step calls `run_verification_at(request, view_revision.next())` (`:396-407`), and that function requires both current revision and request target revision to equal the expected revision (`:659-674`).

[INFERENCE] A request whose scope is built from the revision shown to the model is rejected as outside the current revision after invocation accounting. The user-visible model cannot know the accounting event unless it predicts a future revision.

## Discriminating observation

Use a scripted ModelBackend that returns a `VerificationRequest` targeting the view revision, initialize one known obligation, run one step, and inspect whether the result is `SemanticViolation` before any patch. If the request succeeds in a stable run, this hypothesis is falsified.

## Acceptance criteria

- A scripted model request targeting the exact revision shown in the Cognitive View reaches Runtime/Praxis rather than failing solely because invocation accounting advanced the revision.
- Stale requests from older revisions remain rejected.
- Targeted test, affected-crate integration, and all final gates pass.

## Non-goals

Do not weaken revision checks, remove invocation accounting, change public API, or alter test semantics.
