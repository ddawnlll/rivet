# BUG-007 — Store has no explicit optimistic stale-state/CAS contract

**Status:** OPEN / UNKNOWN-USER-AUTHORITY  
**Priority:** P1  
**Scope manifest:** `crates/rivet-store/src/lib.rs`, `crates/rivet-core/src/lib.rs`, store/core tests only.

## Symptom and evidence

[OBSERVATION] `HardStateStore::append_event` accepts only `&NoesisEvent` and returns a revision (`crates/rivet-store/src/lib.rs:16-22`). `MemoryStore` and `RedbStore` append based on current event count; no expected revision is supplied and no `STALE_STATE` error is emitted. ACCP defines `STALE_STATE` as a signal at `docs/contracts/ACCP_3_0_SPEC.md:1518-1534`.

[INFERENCE] Two Harness instances can independently validate the same base revision and race to append; redb transaction serialization is not the same as semantic expected-revision rejection.

## Open authority question

[UNKNOWN-USER-AUTHORITY] Adding a CAS parameter or changing the store trait is a public API change. Confirm whether the store contract must own CAS, or whether the Harness-level revision lock is the intended first-slice boundary.

No patch was made.
