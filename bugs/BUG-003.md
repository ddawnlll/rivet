# BUG-003 — Unbounded command output

**Status:** IMPLEMENTED / FULL-GATE VERIFIED; REVIEW PROTOCOL-LIMITED  
**Priority:** P1

## Symptom and evidence

[OBSERVATION] Runtime and ExecGate previously converted complete stdout/stderr buffers to strings without a bound, while file-read observations were separately capped.

[INFERENCE] A command producing sustained output could grow memory before timeout or receipt production.

## Root cause and discriminating observation

[OBSERVATION] The new bounded-reader tests run commands that emit substantially more than a 1 KiB configured limit and assert both streams stay within the limit and carry `[output truncated]`. Runtime receipt: [.rivet/audit/evidence/BUG-003-runtime-v3.txt](/C:/Users/dresden/Documents/rivet/.rivet/audit/evidence/BUG-003-runtime-v3.txt). ExecGate receipt: [.rivet/audit/evidence/BUG-003-praxis-pipeline.txt](/C:/Users/dresden/Documents/rivet/.rivet/audit/evidence/BUG-003-praxis-pipeline.txt).

## Final diff summary

[OBSERVATION] Runtime and ExecGate now drain piped stdout/stderr concurrently while retaining at most a configurable limit. The default is 1 MiB; the truncation marker is kept within the limit and output is converted without invalid UTF-8. Praxis exposes the limit through the pipeline builder. File-read caps and command policy were not changed.
