# BUG-003 — Runtime and ExecGate command output is uncapped

**Status:** OPEN / BLOCKED-UNSTABLE-TREE  
**Priority:** P1  
**Scope manifest:** `crates/rivet-runtime/src/lib.rs`, `crates/praxis/src/gates/exec_gate.rs`, focused tests only.

## Symptom and evidence

[OBSERVATION] `Runtime::execute_command` converts the complete child stdout/stderr buffers to `String` with no size bound (`crates/rivet-runtime/src/lib.rs:53-73`). ExecGate does the same (`crates/praxis/src/gates/exec_gate.rs:120-137`). The Runtime file-read observation has a 64 KiB cap, but command output does not.

[INFERENCE] A command that emits unbounded output can consume memory before a timeout or receipt is produced, violating the resource-boundary contract.

## Discriminating observation

Run a bounded child that writes more than the proposed cap and observe peak/result size; the test must also prove the process is reaped and the receipt records truncation.

## Acceptance criteria

- Command stdout and stderr are capped without invalid UTF-8 output.
- Receipts preserve an explicit truncation indication.
- Timeout and failure semantics remain fail-closed.
- Targeted runtime/Praxis tests and all final gates pass.

## Non-goals

Do not remove output evidence, change command allowlists, add dependencies, or weaken timeout tests.

No patch was made because the active edit stream overlaps both allowed files.
