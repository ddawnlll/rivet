# BUG-004 — Timeout cancellation is child-only, not process-group safe

**Status:** OPEN / BLOCKED-UNSTABLE-TREE  
**Priority:** P1  
**Scope manifest:** `crates/rivet-runtime/src/lib.rs` and `crates/praxis/src/gates/exec_gate.rs`; no platform abstraction change without human authority.

## Symptom and evidence

[OBSERVATION] Both command runners use Tokio `kill_on_drop(true)` (`crates/rivet-runtime/src/lib.rs:54-59`, `crates/praxis/src/gates/exec_gate.rs:120-126`). No process-group/session creation or descendant termination code was found in the runtime scan.

[INFERENCE] A timed-out command that spawns a descendant can leave the descendant alive after the direct child is dropped, contrary to the process-group kill requirement.

## Open authority question

[UNKNOWN-USER-AUTHORITY] Confirm whether portable Windows + Unix process-group termination is required for this slice and which platform-specific implementation is approved.

## Acceptance criteria

- A timeout test proves the direct process and a spawned descendant are terminated on supported platforms.
- No leaked process remains after cancellation or timeout.
- Full verification ladder passes.

No patch was made: the required platform policy is unresolved and the files are externally modified.
