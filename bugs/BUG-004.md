# BUG-004 — Process-group termination on timeout

**Status:** WINDOWS HOST VERIFIED / UNIX EXECUTION UNKNOWN; REVIEW PROTOCOL-LIMITED  
**Priority:** P1

## Symptom and evidence

[OBSERVATION] Runtime and ExecGate previously relied on child-only `kill_on_drop(true)` and had no process-group/session or descendant termination path.

[INFERENCE] A timed-out command could leave a spawned descendant alive.

## Root cause and discriminating observation

[OBSERVATION] On Windows, the implementation creates a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, assigns the child, and explicitly terminates the job on timeout. The focused test launches a nested PowerShell sleeper, records its PID, and confirms it is no longer running after timeout: [.rivet/audit/evidence/BUG-004-runtime-v3.txt](/C:/Users/dresden/Documents/rivet/.rivet/audit/evidence/BUG-004-runtime-v3.txt).

[UNKNOWN] The Unix `setpgid`/negative-PID path is present under `cfg(unix)` but was not executable-tested on this Windows host. No Unix runner/toolchain receipt is available.

## Final diff summary

[OBSERVATION] Both Runtime and ExecGate use the same internal managed-child abstraction. Unix creates a process group and kills the negative process-group ID; Windows uses a Job Object. Timeout paths terminate and reap the managed child. No external dependency or platform-specific test hack was added.
