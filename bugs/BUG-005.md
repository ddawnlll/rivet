# BUG-005 — TUI cancellation does not cancel the Harness task

**Status:** OPEN / BLOCKED-UNSTABLE-TREE  
**Priority:** P1  
**Scope manifest:** `crates/rivet/src/tui.rs`, `crates/rivet-core/src/lib.rs`, focused TUI/Harness tests only.

## Symptom and evidence

[OBSERVATION] Ctrl-C/Esc sets `is_processing = false` and displays a cancellation message (`crates/rivet/src/tui.rs:2417-2421`, `:2571-2578`). The work itself is spawned with `tokio::spawn` and only sends a result later; there is no cancellation handle/token (`:2675-2679`). `RunPhase::Cancelled` exists as an enum variant but is not connected to this path.

[INFERENCE] The UI can claim cancellation while the model call, file mutation, or verification continues in the background.

## Acceptance criteria

- User cancellation reaches the running operation and prevents further authoritative work where cancellation is requested.
- The phase and UI receipt distinguish cancelled from completed/failed.
- A focused test proves cancellation during a blocking model/runtime operation.
- Full gates pass.

## Non-goals

Do not change user-facing key bindings or claim cancellation without a mechanical receipt.

No patch was made because the TUI file is actively modified externally.
