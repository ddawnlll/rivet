1. Product thesis

Rivet’s architecture is richer than a chat transcript, but the interface must not mirror every subsystem as a panel. The UI is a projection layer over Rivet state. Its job is to preserve user orientation while making the process observable.

Expose the flow of cognition without exposing the complexity of the machinery.

01
The task owns the center.The primary visual locus is the user’s current objective and Rivet’s current consequential step — never a code diff, tool log, state dashboard or model token stream.
02
Conversation is the surface; the active run is the instrument.At rest Rivet is spacious and conversational. During work, the active turn becomes a structured Live Run object. It does not open seven permanent panels.
03
System architecture does not dictate screen architecture.Goal Compiler, Noesis, ACCP, Praxis and the Harness remain real subsystems; the UI composes their meaningful events into one attention hierarchy.
04
Transparency is selective observability.Rivet exposes goals, hypotheses, commitments, contradictions, verification predicates, authority gates and state transitions — not private chain-of-thought or raw hidden prompts.
05
Implementation is consequence, not identity.Files, patches and diffs are immediately inspectable but secondary. A run returns visually to Praxis and Hard State after an action.
06
Persistent objects change in place.Goals, obligations, contradictions and verified claims retain identity across phases and revisions. Do not create message spam for state that can mutate in place.
Evidence-informed

2. Research constraints

These are design constraints inferred from HCI and typography research. They support the interaction strategy; they do not empirically validate Rivet’s exact layout.

EvidenceDesign implication
Visual complexity affects aesthetic judgment extremely quickly. Tuch et al. found complexity effects within tens of milliseconds.Do not make the opening state information-dense. Complexity must unfold only when work creates a reason for it.
HUD complexity can produce attentional tunneling. Higher visual complexity reduced peripheral target detection in an automotive HUD study.A “cockpit” is not a wall of telemetry. The active step gets one dominant locus; status remains peripheral.
Incremental transparency can become distracting. Users may prefer more transparency in theory but find continuous incremental feedback disruptive in use.Show consequential transitions, not every internal event. Summarize noisy events into stable typed updates.
Dynamic highlighting is attention-hungry under cognitive load.Only one region may carry high-salience motion at a time. Background state cannot pulse competitively.
Motion is a powerful grouping cue. Common-fate research shows coordinated motion can communicate grouping strongly.Use shared trajectories to communicate causal continuity: reasoning → verification → state commit.
Thin weights reduce legibility; dark polarity has readability costs.Dark-first typography must carry enough ink. Body text begins around 425–475 equivalent weight; never “luxury thin.”

3. Attention constitution

Attention is a finite product resource. Every contrast increase, movement, badge, border and live number spends it.

A1
One dominant locus.At any moment the interface MUST have one visually dominant work object. If two things demand immediate reading, hierarchy has failed.
A2
Past recedes; future whispers.Completed phases become low-contrast landmarks. Upcoming phases are visible only enough to preserve orientation. The current phase owns readable detail.
A3
Peripheral state stays peripheral.Open obligations, verification progress and authoritative state remain glanceable, but may not visually outrank the focal process unless they block the user.
A4
Motion spends attention.Only the focal event may use high-salience motion. A second animated region is allowed only when it is causally coupled to the first transition.
A5
Detail follows intent.Evidence graphs, full Cognitive View, raw receipts and implementation artifacts remain closed until the user inspects the relevant object.
A6
No false calm.Minimalism MUST NOT hide blockers, authority requests, contradictions or verification failure. Critical epistemic events may temporarily take focus because they change what work is valid.

Signature primitive

7. Live Run — event stream, not phase UI

Prompt, Goal Compiler, Noesis, tools, ACCP, Praxis and Hard State are runtime concepts. They are not forced into equal-width tabs or a manually advanced wizard. The product renders a chronological stream of consequential events; the newest meaningful event becomes the focal row while older events compress into quiet history.

Event classWhat the user sees liveWhat remains hidden / collapsed
User promptThe exact text the user sent, preserving line breaks and attachments.No rewritten “intent” substituted in its place.
Goal compileObjective / obligation delta when it materially affects the run.Internal bookkeeping noise and giant goal trees.
Reasoning summarySelected hypothesis, contradiction, unknown, decision boundary or scope decision.Private chain-of-thought and token-by-token narration.
Tool callTool identity, useful target and concise result: search · auth refresh · 5 matches, cargo test · auth_refresh · PASS.Raw stdout/stderr unless inspected.
ActionWhat changed and scope: “2 files modified · narrow repair”.Full diff unless requested.
PraxisVerification predicate, progress and result, scoped to what it actually proves.Generic “tests passed” claims.
Hard State mutationAuthoritative delta: O4 OPEN → VERIFIED.No silent mutation.
Authority / blockerMoves to focus immediately when user input is required.Cannot remain buried in history.

Event compression

Do not render every low-level operation. Repeated reads/searches may collapse under one expandable tool event. The rule is not “show everything”; it is “never hide a meaningful change in what Rivet believes, does, verifies or is authorized to claim.”

10. Motion — causality, not decoration

When certainty increases, visual entropy should decrease.

Ambient Rivet Field is optional and extremely low salience. It may react to global runtime state, but it MUST NOT become a screensaver. Reduced-motion mode removes spatial animation and preserves meaning through instantaneous state change, opacity and text.

12. Code and artifacts — one layer deeper

Rivet may produce code, but code-writing is not the product thesis. The Stage communicates intent, diagnosis, action scope, verification and resulting state. Implementation detail is available immediately without occupying the main visual hierarchy.

Action summary

Main Stage: “Applied a narrow repair to refresh validation · 2 files.” This is enough unless implementation detail is the current user task.

Implementation Studio

On inspect: diff, file history, semantic patch, raw tool output, rollback, generated artifacts and provenance.

Return path

Closing Implementation Studio returns to the exact Live Run object and phase. Attention then continues toward Praxis, not toward the diff.

14. Accessibility and robustness

Typography & contrast

Do not use Thin/Light UI text. Verify WCAG contrast for primary and secondary text on actual dark surfaces. UI must survive text scaling without hiding state or controls.

Motion

Respect prefers-reduced-motion. No meaning may depend solely on spatial animation. Motion-triggered interfaces must remain fully understandable when transitions become instantaneous.

Keyboard

Every inspectable epistemic object is focusable. Aperture, run navigation, cancel, history, palette and implementation inspection must work without a pointer.

Color independence

Verified, provisional, blocked and contradictory states must differ through text, geometry or border treatment in addition to color.

17. Anti-patterns

Information pornography

Goal Compiler card + Noesis card + Reasoning card + Praxis card + Hard State card all visible at once. This mirrors architecture instead of designing an interface.

Generic agent shell

Permanent project sidebar + chat + diff panel, with “Thinking…” spinner and code dominating every active turn.

AI visual clichés

Neon violet/cyan gradients, particle brains, excessive glass, floating pill forests, glowing borders, decorative waveform cognition.

False transparency

Token-by-token hidden reasoning theatre, fake confidence, frontend-invented states or raw traces presented as epistemic truth.

False minimalism

Hiding verification failure, blockers or state changes to preserve an empty black screen. Calmness does not outrank correctness.

Motion spam

Multiple pulsing regions, decorative ambient animation during critical work, or transitions that delay input/cancel/verification visibility.

Ship gate

18. Design acceptance criteria

Ten-second test

A new user looking at an active run for ten seconds should be able to answer:

01
What is Rivet trying to accomplish?
02
What phase of work is active now?
03
What is the single most important current finding / action / verification?
04
Is completion blocked, and if so by what?
05
Has authoritative state actually changed yet?

Prototype MUST include

01  Bricolage Grotesque + IBM Plex Mono typography system
02  black-first Stage with restrained Project Edge
03  idle conversation state with low visual complexity
04  one Live Run object that changes in place
05  raw user prompt preserved exactly as sent
06  real composer controls: attach, send/steer, model selector, project context and project settings
07  chronological live event stream: goal compile, reasoning summary, tool calls, actions, Praxis and Hard State mutations
08  only the newest consequential event receives high visual salience
09  selected typed reasoning commitments — never raw private chain-of-thought
10  visible tool calls with concise target/result; raw output on inspect
11  visible authoritative state mutation when it actually commits
12  Cognitive Aperture that expands from the inspected event
13  code/diff hidden behind implementation inspection by default
14  completed run collapses into a compact reopenable receipt
15  keyboard navigation, immediate cancel, reduced-motion fallback and all state derived from real RivetService / UiEvent contracts

Failure conditions

Reject the implementation if the eye does not know where to look; if the user’s raw prompt is replaced by an interpreted card; if the shell loses basic product controls such as project/model/settings/attachments/send; if code occupies the center by default; if meaningful tool calls are invisible; if the user must scan multiple simultaneous subsystem panels to understand progress; if Hard/Soft authority is visually ambiguous; if “done” can appear before required Praxis obligations close; or if removing animation removes meaning.

Final position

20. Rivet should feel like a precision cognitive machine.

Not empty. Not noisy. Powerful enough to inspect, calm enough to think.

The signature is not a gradient, a sidebar or a diff viewer. It is the interaction grammar: one stable work locus, visible consequential cognition, peripheral epistemic awareness, evidence on demand, verification that closes the loop, and authoritative state that becomes quieter as it becomes more certain.
